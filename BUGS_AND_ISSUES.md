## 4. Технический долг

### Архитектурный
1. **Идентификация устройства** — с 16.11 токен в `localStorage` (`by_token`), адрес — резерв;
   остаётся случай потери токена (очистка данных сайта) → новый id.
2. **Комнаты в памяти** — нет персистентности; после рестарта все передачи теряются.
3. **`Shared` с 8 мьютексами** — работает, но блокировки легко перепутать порядком;
   в `pc_pending` и `push_room` порядок `reqs → devices` совпадает, это нужно сохранять.
4. **`include_str!` для страницы** — правка HTML требует пересборки exe.
5. **Часть логики продублирована в JS** (например, знание про состояние комнаты
   и про то, кто отправитель) — при изменении протокола править два места.

### Дублирование кода
- Построение JSON строками вручную (`format!`) в 10+ местах — риск опечаток и
  отсутствия экранирования; заменяемо на `serde_json::json!`/derive-структуры.
- `esc`/`clean_label`/`safe_rel_path` используются по-разному: часть хендлеров возвращает
  JSON, собранный вручную.

### Ненадёжные участки
- `upload`: при ошибке записи удаляет `.part`, при обрыве тела — нет; логика различается
  в двух ветках, при рефакторинге легко сломать докачку.
- `prune` вызывается не везде (например, не в `upload`), поэтому устройства исчезают
  с задержкой до следующего запроса.
- Таймеры (`spawn` с `sleep`) не отменяются при закрытии комнаты — лишние пробуждения,
  безвредно, но мусор.

### Производительность
- Один файл = один HTTP-запрос с телом целиком; для 4 ГБ на слабом телефоне это
  продолжительное соединение (для не-Apple нет нарезки).
- `/api/state` опрашивается каждые 3 с каждым устройством — дёшево, но при 20 устройствах
  это 20 запросов/3 с.

### Тесты
- 3 юнит-теста на серверную логику; ни одного теста на `page.html` и на HTTP-слой.
- Ad-hoc скрипты проверки лежат вне репозитория (`C:\Temp\opencode`), не версионируются.

### Документация
- До 16.11.2026 документации не было вообще; эти 6 файлов — первые.

## 5. Как проверять известные проблемы

| ID | Как воспроизвести/проверить |
|---|---|
| B-01 | Зайти с телефона, сменить Wi-Fi/переподключиться с другим IP → в списке появится новое устройство |
| B-03 | На iPhone выбрать 5 файлов, нажать «Загрузить всё» → Safari спросит разрешение на каждую загрузку |
| B-04 | Передать файл 100 МБ на телефон → скачивание без полосы прогресса |
| B-05 | Занять порт 8765 (`python -m http.server 8765`), запустить NeonSend → сервер уйдёт на 8766, телефон не подключится |
| B-11 | Дважды подряд создать передачу между теми же двумя устройствами и запустить обе — файлы смешаются в одной папке |
| R-03 | Загрузить файл, имя которого совпадает с именем существующей папки в папке приёма |

## 6. Что НЕ является проблемой (проверено и работает)

- Path traversal (`../../evil.txt`) → 400.
- Абсолютный путь `C:/Windows/evil.txt` → превращается в `C_/Windows/evil.txt` внутри корня.
- Зарезервированные имена (`con.txt`) → `_con.txt`.
- Чужой Origin → 403 «чужой источник».
- Загрузка без подтверждения комнаты → 403 «передача не разрешена» (проверено curl-ом 16.11: без `req`, с несуществующим `req`, при комнате в `wait`, после `sender_done`).
- `/dl` и `/api/part` без комнаты или от чужого устройства → 403.
- Загрузка чужим устройством по чужому `req` → 403.
- Переименование чужого устройства → `{"error":"это не ваше устройство"}`.
- Повторный `answer` не меняет уже принятое решение.
- Уход отправителя → комната Abort, получатель уведомлён.
