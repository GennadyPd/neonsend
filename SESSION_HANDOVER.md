## 1. Что мы делаем

Локальный обменник файлов: один `.exe` на ПК, клиенты — браузеры в той же Wi-Fi/LAN-сети.
Запустил → в окне QR и адрес `http://192.168.1.25:8765` → телефон, планшет или ТВ открывает
страницу → передаёт файлы или текст. Без установки приложений, без интернета, без аккаунтов.

Сейчас реализован полный сценарий: имя устройства → список устройств → ожидание подтверждения →
отправка с прогрессом → получение всех файлов или текста. Передача телефон→телефон идёт
через ПК в папку `Temp(отправитель-получатель-номер-комнаты)`; папки автоматически
не удаляются — в окне есть кнопка «Удалить временные папки».
Окно exe — **только панель**: подтверждения приёма делает страница в браузере (в том числе
на самом ПК, id `0`).

16. Пакет правок по аудиту (16.11, вечер) — то, чего не хватало по документации:

      `events` ищет устройство по `by_token` (IP остался резервом) — «меня зовут заново»
      и скачки `me` после перезагрузки прекратились;
    - **список файлов получателю**: `announceStart` отправляет в `/api/push` тело
      `[{name,size}]`, сервер кладёт его в `Req.planned`, оверлей подтверждения и экран 4
      показывают имена, размеры и итог; на экране 4 добавлены скорость и «осталось»;
    - **очередь отправителя** со статусами файлов («отправляется / в очереди / ошибка»);
    - **уникальная Temp-папка** `Temp(отправитель-получатель-номер-комнаты)`;
    - **отвязка комнаты после `Done`** (`d.room = None`, страница возвращается на экран 2);
      для комнат «на ПК» сервер сам завершает передачу (`maybe_finish`), когда отправитель
      сообщил `sender_done` и все файлы дошли;
    - **`.part` удаляются при `Abort`** (и при уходе устройства);
    - **таймаут простоя upload**: 60 с без данных → `408`, `.part` остаётся для докачки;
    - **плашка «связь потеряна, переподключаюсь»** с кнопкой на странице;
    - **окно-панель**: блок «ПЕРЕДАЧИ» (кто → кому, состояние, прогресс), строка
      `Temp: … · свободно на диске: …`, кнопка «Открыть папку приёма», понятное сообщение
      при занятых портах 8765–8790;
    - кнопки на странице не меньше 44 px.

Проверено вживую: список файлов в подтверждении (2 файла 5000 и 7000 б, имена видны

## 9. Решения, которые нельзя пересматривать без причины

1. **HTTP без TLS** — иначе красные экраны и установка сертификатов (см. `DECISIONS.md` R-02, R-03).
2. **Устройство = токен в браузере (IP — резерв)** — решено 16.11 вместо «устройство = IP» (D-05).
3. **Формат Temp-папки `Temp(от-кому-номер-комнаты)`** — на него завязаны `upload`, `/dl`, `/api/part`, `exists`, `delete_temps`.
4. **Состояние передачи на сервере + SSE**, а не в памяти вкладки.
5. **ПК — устройство id=0**, подтверждение на странице в браузере; окно только панель.
6. **Никаких имён файлов в журнале окна** — требование приватности.
7. **Один .exe без WebView2 и без установки компонентов.**
8. **Клиенты — только браузеры**; приложения на телефоны не ставим.
9. **Временные файлы на ПК** телефон→телефон копятся в `Temp(...)` и удаляются вручную кнопкой в окне.
10. **Короткий адрес `neon.local` (mDNS) не используется** — удалён 16.11, на Android не резолвился.
11. **`panic = "abort"` в release запрещён** — паника окна не должна ронять сервер (это уже стоило
    жизни процессу посреди передачи). Сервер поднимается в `boot()` один раз, окно рисуется под
    `catch_unwind` и перезапускается после паники egui.
12. **Папка приёма по умолчанию — `Загрузки\NeonSendTemp`**, Temp-папки кладутся внутрь неё.
13. **Текст передаётся как текст, не файлом** (`Req.text`), HTML на странице не исполняется.
14. **Без новых зависимостей** (в т.ч. для таймаутов HTTP — `tower` резал бы SSE).
