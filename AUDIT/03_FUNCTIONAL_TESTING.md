## Найденные функциональные дефекты
- **NS-FUN-01 (MEDIUM)**: размер файла в комнате = размер последнего чанка. Для iOS (>8 МБ всегда чанками) прогресс, суммарный объём и порог 64 МБ считаются неверно.
- **NS-FUN-02 (MEDIUM)**: файлы >64 МБ отдаются прямой ссылкой — нет прогресса/докачки (B-04).
- **NS-FUN-03 (MEDIUM)**: в фоновой вкладке SSE отваливается, состояние застревает до reload (B-17).
- **NS-FUN-04 (LOW)**: `loadState` не сбрасывает комнату, если `j.room` null, а state не done/abort → на экране висит старая передача.
- **NS-FUN-05 (LOW)**: Temp-папки relay не удаляются после Done/clear (проверено: 221 МБ остались).
- **NS-FUN-06 (LOW)**: остатки `.part` после сбоя (в папке приёма лежит `IMG_3396.MOV.part` 40 МБ).
- **NS-FUN-07 (LOW)**: порт-фолбэк 8765→8790 молча меняет URL; второй экземпляр приложения может подняться на 8766 и иметь своё состояние.
- **NS-FUN-09 (LOW)**: панель журнала фиксированной высоты, записи обрезаются снизу (видно на скриншоте окна).

## Проверки на граничных значениях
- Пустое имя файла, `..`, абсолютные пути, `CON`, имена с пробелом/точкой на конце — отклоняются или обезвреживаются (`safe_rel_path`).
- `/api/part?name=../../etc` → 400 «недопустимый путь».
- `POST /api/ping` → 405, неизвестный маршрут → 404, `/dl` без параметров → 400.
- Тело `exists` объектом вместо массива → 400 «ожидался список имён» (проверка формата есть).
- Чанк без предшествующего `.part` при `off>0` → 409 «кусок пришёл раньше начала файла» (защита есть).

## Вывод
Основной пользовательский путь (выбрать файлы → подтвердить → передать → скачать) работает и целостен. Дефекты концентрируются вокруг больших/чанковых передач и жизни Temp-данных.
