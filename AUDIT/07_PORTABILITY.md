# 07. Portability

## Целевая среда
Windows 10/11 x64, один exe, браузеры в LAN. Собрано и проверено на текущей машине (Windows, rustc + mingw64 toolchain, `cargo build --release` → 0.26 с инкрементально, exe 5 266 432 б).

## Что переносимо
- Один бинарник: не требует установки, WebView2, MSVC-рантайма (mingw), внешних сервисов.
- Конфиг и данные в `%APPDATA%\NeonSend` (portable-режима нет, но папку можно скопировать).
- Работает в любой LAN с IPv4; порт выбирается из диапазона 8765–8790.

## Ограничения (находки)
### NS-PORT-01 — LOW — доступ по имени компьютера ломает API
`guard` требует Host ровно `ip:port` / `localhost:port` / `127.0.0.1:port`. Открытие `http://pc-name:8765` → 403 на всех `/api/*` (страница откроется, но передачи не работают). Пользователь не получает понятной подсказки. Рекомендация: либо разрешать Host, совпадающий с именем машины, либо явно писать в UI «открывайте по IP».

### NS-PORT-02 — LOW — порт-фолбэк и второй экземпляр
Если 8765 занят, сервер молча берёт следующий порт (до 8790); URL/QR показывают фактический, но в документации и правилах firewall фигурирует 8765. Второй запущенный экземпляр приложения поднимется на другом порту со своим пустым состоянием — пользователь может не заметить, что устройства «пропали». Рекомендация: single-instance mutex или предупреждение в UI.

### NS-PORT-03 — INFO — только IPv4, только Windows
`local_ip()` выбирает IPv4 приватного диапазона; IPv6-сети не поддержаны. FFI `GetDiskFreeSpaceExW`, `rundll32`, `%APPDATA%`, лимит MAX_PATH 260 (R-04) — перенос на Linux/macOS потребует переписывания частей `main.rs`.

### NS-PORT-04 — INFO — сетевые условия
- Изоляция клиентов на Wi-Fi (AP isolation) и гостевые сети блокируют соединения — типичная причина «не видит устройства».
- Firewall: правило создаётся/ожидается по программе, а не по порту (R-16); после обновления exe путь тот же.
- iOS/Safari: фоновая вкладка засыпает (R-05), wake lock через canvas-видео — фолбэк; большие файлы чанками. Реальный тест 5.9 ГБ после фикса не проводился (B-19).

### NS-PORT-05 — INFO — диск и пути
- Имя Temp-папки зависит от меток (`Temp(PC-1-Phone-5)`) — при длинных метках и глубокой папке приёма возможен MAX_PATH (R-04).
- Мало свободного места не блокирует старт передачи заранее; проверка только в UI (149 ГБ в тесте).

## Мобильные клиенты (наблюдения)
- Android Chrome: полный цикл работает, SSE держится в активной вкладке, скачивание через `/dl` корректно.
- iPhone: основной сценарий заявлен рабочим, но в этом аудите не проверялся (нет устройства); известные ограничения — множественные автозагрузки (B-03), фон (R-05), большой файл (B-19).

Оценка переносимости: **5/10** — идеально для «Windows + домашняя LAN», плохо для смешанных сетей и не-Windows.
