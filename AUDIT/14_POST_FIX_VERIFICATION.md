## 1. Что изменено

### `src/server.rs`
| Находка | Изменение |
|---|---|
| SEC-01 | Middleware `auth` на всех маршрутах, кроме `/`, `/api/events`, `/api/ping`. Токен из query `t` ищется в `by_token` и должен указывать на живое устройство; параметры `id`/`from` обязаны совпадать с ним. Иначе 403 «нужна авторизация» / «это не ваше устройство». Проверенное устройство кладётся в `Extension<DevId>`. |
| SEC-01 | `answer` принимает только получатель комнаты; `done` — только участник; `leave` без участника отвечает `{"ok":true}` и ничего не делает. |
| SEC-02 | `exists` — только участник комнаты (или ПК без `req`); `part_size` — только участник, добавлен `id`; `download` уже требовал `id==from|to`, теперь id подтверждён токеном. |
| SEC-03 | Потолок одновременных комнат: 64 → «слишком много передач — попробуйте позже». |
| SEC-04 | `lock()` helper с `unwrap_or_else(|e| e.into_inner())`; все 76 `lock().unwrap()` заменены. |
| SEC-05/06 | Middleware `headers`: `X-Frame-Options: DENY`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`, CSP для `/`, `application/json; charset=utf-8` для API-ответов без типа. |
| SEC-07 | При `off>0` сверяется длина `.part`: `off > have` → 409 «кусок не совпадает с началом файла». |
| FUN-01 | `items[].size = off + written`, запись обновляется, а не дублируется; лог пишет полный размер. |
| — | Токен локального ПК теперь тоже регистрируется в `by_token` (иначе после включения auth страница ПК получала 403). |

### `src/page.html`
- Глобальная обёртка `fetch` добавляет `t=<token>` ко всем `/api/...` и `/dl` — иначе после включения auth клиент ломался бы.
- `connect()`: переподключение SSE через 3 с, скрытие/показ `#lost`, переподключение при возврате на вкладку (`visibilitychange`) — FUN-03.
- `room = j.room || null` — устаревшая комната больше не залипает (FUN-04).
- `/api/part` вызывается с `&id=`.
- Доступность: `<h1 class="sr-only">`, `<label for="nameInput">`, `role="progressbar"` + `aria-valuenow` у обеих полос, `aria-labelledby` у модалок, фокус на первой кнопке, Tab-ловушка в модалках, стрелки в меню темы, чип темы 44 px.
- Контраст `--faint` поднят до ≥4.5:1 во всех четырёх темах (neon `#7a8b84` — 5.55:1).

## 5. Проверки на реальном Android (adb)

Устройство: `SERIAL`, Android 10, Chrome 157, IP 192.168.1.4 (`adb forward tcp:9223` → CDP). Телефон — устройство id 1 «Phone», ПК — id 0 «PC-1».

| Проверка | Результат |
|---|---|
| Регистрация устройства и SSE | токен в `localStorage`, `named: true`, ошибок консоли нет |
| Отправка файла 2 МБ с телефона на ПК через UI | комната 14, «1 из 1 за 0.2 с», файл 2 097 152 б на ПК |
| Приём на телефоне (ПК отправитель) | приглашение «PC-1 хочет передать вам файлы (1). Принять?» → `scr4` → скачивание → завершено |
| Целостность | файл на телефоне 2 097 152 б, **sha256 совпал** с исходником |
| Чанковая загрузка 5 МБ (2 куска) | 200/200, `items[0].size = 5 242 880` — FUN-01 исправлен |
| `/dl` файлов, принятых на ПК | 200, 1000 б, байты совпали, `Content-Disposition: attachment` |
| Методы | `request/answer/clear/sender_done/done` только POST, GET → 405 |

### Найдено и исправлено в ходе теста

1. **Регресс auth на `/api/answer`** — middleware сравнивал `id` (номер комнаты) с id устройства → согласие было невозможно (403). Теперь для `/api/answer` проверка `id`/`from` пропускается, участника проверяет хендлер. Проверено: ПК принимает (200), телефон на чужую комнату получает `{"error":"это не ваша передача"}`.
2. **`/dl` для файлов на ПК** — база всегда `root.join(temp)`, а при `to == PC_ID` файлы лежат в `root` → 404. Теперь база выбирается по получателю. Проверено: 200 и совпадение байтов.

### Подтверждено вживую

- **Падение egui 0.28 (BE-05 / F-50):** 6 паник `hit_test.rs:269: called Option::unwrap() on a None value` подряд (10:04:47–10:04:51), окно перезапустилось 5 раз и приложение завершилось. Лечится только egui ≥0.37 (переписывание окна).

### Наблюдения (не дефекты приложения)

- Файл, залитый `adb push` (owner root, `chmod` на sdcardfs игнорируется), Chrome не может прочитать → `Failed to fetch` / «0 Б». С файлом, скачанным самим Chrome, отправка работает. Стоит давать более внятное сообщение (INFO).
- Ранний отказ сервера (403/409) без чтения тела большого запроса вызывает `ECONNRESET`, клиент показывает «Failed to fetch» (мелкий UX-дефект).

## 7. Сеть и второй экземпляр (16.11, после аудита переноса)

- Сервер слушает `0.0.0.0`: адрес в QR больше не привязан к bind, отвечают и `127.0.0.1`, и `localhost`, и любой LAN-IP.
- В окне появился выбор сети («сеть:» + список), если у ПК больше одного адреса; выбор сохраняется в `config.json` (`ip`), QR и ссылка обновляются сразу, без перезапуска сервера.
- Guard переписан: Host обязан быть `localhost` или IP-литералом из локальных сетей с нашим портом, Origin/Referer должен совпадать с Host. Hostname по-прежнему отклоняется (DNS rebinding закрыт).
- Второй экземпляр: при запуске проверяется `127.0.0.1:8765/api/ping`; если сервер уже работает — окно показывает «NeonSend уже запущен», второй сервер не поднимается и на 8766 не уходит.

Проверки: `curl` с Host `evil.com` / чужим портом → 403 «чужой адрес»; чужой Origin → 403 «чужой источник»; свои Host/Origin, localhost, 127.0.0.1 → проходят guard; `audit_auth.mjs` 25/25; `tests/ui_smoke.mjs` 8/8; скриншот второго окна `C:\Temp\opencode\win_second.png`; сборка и `cargo test --release` 7/7 без предупреждений.

Не проверено на живом экране: сам список сетей (на этом ПК один LAN-адрес, переключатель не отображается); смена адреса во время активной передачи.

- IPv6, AP-isolation, не-Windows клиенты.
