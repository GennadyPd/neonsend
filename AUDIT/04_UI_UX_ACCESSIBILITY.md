# 04. UI/UX & Accessibility

## Что смотрели
Скриншот окна приложения (`C:\Temp\opencode\win.png`, 576×979 при окне 560×940), программные метрики живого DOM (Android Chrome, CDP), исходный CSS/JS, расчёт контраста WCAG 2.1 для всех 4 тем. Скриншоты веб-страницы получить не удалось (экран телефона выключен, Chrome на ПК закрыт, `Page.captureScreenshot` таймаутил) — визуальная оценка веб-части по коду + метрикам, это отмечено как пробел в доказательствах.

## Сильные стороны
- Чистая визуальная иерархия: подключение (QR + URL) → приём файлов → передачи → устройства → журнал.
- 4 темы (neon/cyber/purple/light), аккуратные тени, скругления, `prefers-reduced-motion`.
- Доступность частично заложена: `aria-expanded`, `role="listbox"/"option"`, `role="status"`, `role="log"`, `aria-modal`, `:focus-visible` outline, `lang="ru"`, `viewport-fit=cover`.
- Крупные кнопки (min-height 44 px у основных), понятные подписи, статус «работает» с цветовой точкой и текстом (не только цветом).
- Состояния ошибок/потерь (`#lost`) и модалки переименования/дубликатов продуманы.

## Находки
### NS-UX-01 — MEDIUM — нет структуры документа и лейбла поля имени
Измерено в DOM: `h1–h4` — **0**, landmarks — 2; у `#nameInput` нет ни `<label for>`, ни `aria-label`. Скринридер не объявляет назначение поля и не даёт навигации по заголовкам. Рекомендация: `<h1 class="sr-only">NeonSend — передача файлов</h1>`, `<label for="nameInput">Имя устройства</label>` (можно визуально скрытый), `main/header` секции.

### NS-UX-02 — MEDIUM — контраст ниже AA
Расчёт (WCAG, относительно `--bg`/`--surface`):
| Тема | `--faint` на bg | на surface | Вердикт |
|---|---|---|---|
| neon | 3.52 | 3.35 | только крупный текст |
| cyber | 3.29 | 3.08 | только крупный |
| purple | 3.26 | 3.09 | только крупный |
| light | **2.48** | **2.70** | fail |
Дополнительно в light-теме `--neon #09a257` на фоне = 3.05 (акцентный текст ниже AA). `--faint` используется для подсказок, размеров, футера, времени в журнале — мелкий текст. Остальные пары проходят: `--text` 15.5–18.2, `--muted` 4.7–6.8, `--danger` 4.7–7.6, `--warn` 4.8–14.
Рекомендация: поднять `--faint` до ≥4.5 (например, neon `#7b8983`, light `#5f7368`), в light-теме затемнить `--neon` до `#078347`.

### NS-UX-03 — MEDIUM — модалки без focus-trap и имени
2 модалки (`aria-modal`), 0 элементов с `aria-labelledby`, у модалок нет `id`. Фокус не удерживается внутри, Escape/возврат фокуса не гарантированы. Рекомендация: `id` + `aria-labelledby` на заголовок, простой focus-trap (keydown Tab), возврат фокуса на кнопку-инициатор.

### NS-UX-04 — LOW — прогресс не озвучивается
Элементы прогресса без `aria-live`/`role="progressbar"` с `aria-valuenow` (найдено 0). Рекомендация: `role="progressbar"` с `aria-valuemin/max/now` + `aria-live="polite"` на статусную строку.

### NS-UX-05 — LOW — мелкая цель нажатия
Кнопка-чип темы — высота 36 px (<44 px). Остальные кнопки проходят порог. Рекомендация: `min-height:44px` для чипа или увеличить padding.

### NS-UX-06 — LOW — клавиатура и диалоги
`role="listbox"` без навигации стрелками (реализованы только клики); `confirm()` — нативные диалоги, не стилизованы и блокируют поток. Рекомендация: обработка ArrowUp/Down/Home/End, замена `confirm()` на существующую модалку.

### NS-UX-07 — INFO — журнал обрезается
На скриншоте окна нижняя часть журнала уходит за край (фиксированная высота 222 px, B-18). Пользователь видит только последние строки без возможности прокрутить весь список в пределах окна (прокрутка внутри панели есть, но панель упирается в низ). Рекомендация: дать журналу `min-height` + скролл или сделать окно/секции адаптивными.

## UX-замечания без дефекта
- Тексты понятные, на русском, без жаргона; «наведите камеру телефона на QR-код» — хорошая подсказка.
- Список «Сохранённые» с чекбоксами выглядит как выбор получателя, но не подписан явно — потенциальная путаница (INFO).
- Нет скелетонов/спиннеров на долгих операциях >64 МБ (следствие NS-FUN-02).
- Кнопка «Открыть в браузере» рядом с «Копировать» — хорошая пара, но обе мелкие (28 px по скриншоту).

## Вывод
UX — 7/10: продукт приятный и быстрый. Доступность — 5/10: базовые ARIA есть, но структурная семантика, контраст и модалки не дотягивают до WCAG AA. Правки дешёвые (в основном CSS + несколько атрибутов).
