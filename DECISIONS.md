# NeonSend — журнал решений (ADR)

Формат: ID, этап/дата, контекст, решение, причина, альтернативы, последствия, статус,
источник подтверждения.

**Источник** — откуда известно: `пользователь` (явно подтверждено в переписке),
`код` (видно в реализации), `проверка` (подтверждено запуском/скриншотом),
`предложение ИИ` (не подтверждено явно пользователем).

Статусы: `принято`, `отклонено`, `отложено`, `заменено`.

# Часть A. Принятые решения

## D-01. Rust + один переносимый .exe, GNU-toolchain
- **Этап:** старт проекта (после Python-прототипа).
- **Контекст:** нужен один файл, который запускается без установки и переносится на флешке;
  на машине нет MSVC/VS Build Tools и нет админских прав для их установки.
- **Решение:** Rust 1.100.0, host `x86_64-pc-windows-gnu`, MinGW-w64 GCC 16.2.0, статическая
  линковка, release-профиль с `lto`/`strip` → ~3.7 МБ.
- **Причина:** единственный тулчейн, который ставится без прав администратора и без Visual Studio.
- **Альтернативы:** MSVC-тулчейн (отпал — нет компонентов), Go/C# (не рассматривались всерьёз),
  Electron (тяжёлый, требует Node).
- **Последствия:** все правки нужно проверять на GNU-линковке; часть крейтов с C-зависимостями
  требует наличия mingw в PATH.
- **Статус:** принято. **Источник:** пользователь + код.

## D-02. Нативное окно на egui/eframe, без WebView2
- **Этап:** выбор GUI.
- **Решение:** `eframe`/`egui` (0.27 при выборе, 16.11 обновлены до **0.28**), всё рисуется самим приложением.
- **Причина:** WebView2 требует установленного рантайма (на старых Windows его нет),
  а пользователь требовал «без установки дополнительных компонентов».
- **Альтернативы:** WebView2/Tauri (отклонено), Qt (тяжёлая зависимость), WinAPI вручную.
- **Последствия:** UI ограничен возможностями egui; QR рисуется вручную в текстуру.
- **Статус:** принято. **Источник:** пользователь + код.

## D-03. HTTP без TLS
- **Этап:** после исследования совместимости.
- **Решение:** страница открывается по `http://<ip>:<port>`, сертификаты не используются.
- **Причина:** самоподписанный сертификат даёт красный экран/предупреждение на каждом
  устройстве и каждом сеансе (Android — «Proceed», iOS — «Show Details → visit»);
  локальный CA требует установки профиля на iPhone, что пользователь отверг.
  Пользователь прямо сказал, что красный экран его устроит, но практика показала, что
  без TLS проще и надёжнее для «друзей с айфонами».
- **Альтернативы:** self-signed TLS (отклонено), локальный CA (отклонено), туннель через
  интернет (противоречит «всё локально»).
- **Последствия:** нет secure context → недоступны File System Access API, clipboard,
  ServiceWorker, `crypto.subtle`, `getUserMedia`. Работают fetch/XHR, `<input type=file>`,
  `<a download>`, IndexedDB, `RTCPeerConnection`.
- **Статус:** принято. **Источник:** пользователь + код.

## D-04. Клиенты — только браузеры, ничего не устанавливать
- **Решение:** единственный клиент — `page.html`, отдаваемая сервером.
- **Причина:** «даже если придут друзья с айфонами» — установка приложения на iPhone
  невозможна/нежелательна.
- **Последствия:** все ограничения браузеров (память вкладки, автозагрузки, фон) становятся
  ограничениями продукта.
- **Статус:** принято. **Источник:** пользователь.

## D-05. Устройство = IP-адрес
- **Решение:** id устройства выдаётся по IP; перезагрузка страницы и другой браузер на том же
  телефоне остаются тем же устройством.
- **Причина:** первая версия плодила дубликаты устройств при перезагрузке вкладки.
- **Последствия:** смена IP = новое устройство; два устройства за одним NAT сливаются;
  все вкладки одного IP делят одну комнату.
- **Статус:** принято (компромисс). **Источник:** код + жалоба пользователя на дубликаты.

## D-06. Состояние передачи живёт на сервере, страница — представление
- **Решение:** комнаты, прогресс и статусы хранятся в `Shared`; клиент получает их через
  `/api/state` (раз в 3 с) и SSE `/api/events`.
- **Причина:** нужно видеть процесс с любого браузера устройства и переживать перезагрузку
  вкладки; при закрытии вкладки отправителя сервер сам прерывает передачу.
- **Альтернативы:** состояние в JS-памяти вкладки (терялось при F5).
- **Последствия:** сервер доверяет клиентскому `/api/progress`; нет серверной валидации объёма.
- **Статус:** принято. **Источник:** пользователь («чтобы можно было открыть с любого браузера
  и тоже смотреть процесс») + код.

## D-07. ПК — устройство с id=0 («Этот компьютер»)
- **Решение:** ПК показывается в списке получателей; запрос на ПК подтверждается кнопками
  в egui-окне (`pc_pending`/`pc_answer`), файлы пишутся прямо в папку приёма.
- **Причина:** пользователь жаловался, что при выборе ПК «пишет примите подключение, но
  сообщение не появляется» — окно не было участником протокола.
- **Последствия:** ПК нельзя удалить из списка, пока выбрана папка; для этого случая
  Temp-папка не используется.
- **Статус:** принято. **Источник:** жалоба пользователя + код.

## D-08. Дубликаты решает отправитель (3 режима, в т.ч. по каждому файлу)
- **Решение:** при совпадении имён показывается диалог «Заменить / Пропустить / Переименовать»
  + «Показать список» с выбором по каждому файлу.
- **Причина:** изначально предлагалось решать получателю, пользователь перенёс решение на
  отправителя.
- **Последствия:** замена по умолчанию, переименование через суффикс « (1)».
- **Статус:** принято. **Источник:** пользователь (изменение рекомендации ИИ).

## D-09. Передача телефон→телефон через ПК, но во временную папку
- **Решение:** файлы пишутся в `<папка приёма>/Temp(имя-отправителя-имя-получателя)`,
  получатель скачивает их оттуда, после «Я загрузил всё» папка удаляется.
- **Причина:** пользователь: «файл сразу передавался с телефона на телефон без посредников»
  + «когда файлы передаются между другими устройствами, пусть в папке создаётся папка Temp,
  а после завершения папка удаляется вместе с файлами».
- **Альтернативы:** писать в основную папку (отклонено — файлы оседали на ПК);
  P2P WebRTC (отложено, см. R-01).
- **Последствия:** имя папки зависит от имён устройств; смена имени во время передачи
  не переименовывает папку (папка фиксируется при создании комнаты).
- **Статус:** принято. **Источник:** пользователь + код.

## D-10. Нарезка файлов по 8 МБ для iOS/Safari
- **Решение:** `isApple && size > CHUNK(8 МБ)` → последовательные куски с `off`/`last`.
- **Причина:** Safari на iPhone падает по памяти на больших телах запроса.
- **Последствия:** для остальных браузеров — один запрос на файл (быстрее).
- **Статус:** принято. **Источник:** исследование + код.

## D-11. Докачка через `.part`
- **Решение:** пишем в `.part`, при обрыве соединения оставляем его, клиент запрашивает
  `/api/part` и досылает остаток.
- **Причина:** пользователь просил докачку; ранее реализация удаляла `.part` при обрыве,
  что делало докачку невозможной.
- **Ограничение:** содержимое префикса не сверяется (см. `shortcut:` в `upload`).
- **Статус:** принято. **Источник:** пользователь + код.

## D-12. Конфиги в `%APPDATA%\NeonSend`, данные — рядом с папкой приёма
- **Решение:** `config.json` (папка, тема) и `devices.json` (ip→имя) в `%APPDATA%`;
  перенос exe не сбрасывает настройки.
- **Причина:** портативность при сохранении привычек пользователя.
- **Последствия:** при переносе на другой ПК настройки не переезжают автоматически.
- **Статус:** принято. **Источник:** код + пользователь («помнить последнюю папку»).

## D-13. Четыре темы, отдельно для окна и страницы
- **Решение:** неон (по умолчанию), киберпанк, фиолетовая, светлая; выбор запоминается
  независимо (COMBO в окне, `<select>` на странице).
- **Причина:** пользователь просил выпадающий список тем в углу и светлую тему «не по умолчанию».
- **Статус:** принято. **Источник:** пользователь + код.

## D-14. Журнал без имён файлов
- **Решение:** в окне только количество, %, объёмы, время; имена файлов не печатаются.
- **Причина:** прямое требование пользователя (приватность и «не захламлено»).
- **Последствия:** отладка сложнее — смотреть имена можно только в файловой системе.
- **Статус:** принято. **Источник:** пользователь.

## D-15. Без PIN; защита — подтверждение на получателе + проверка Host/Origin
- **Решение:** нет пароля/токена; есть `guard` (Host/Origin/Referer) и ручное подтверждение.
- **Причина:** исследование аналогов (LocalSend, Snapdrop, Warpinator) показало, что
  подтверждение на устройстве + случайный id достаточно для дома; PIN у LocalSend
  необязательный и статический.
- **Последствия:** любой в сети может открыть страницу; для офиса не годится.
- **Статус:** принято для домашней сети. **Источник:** пользователь (вопрос про PIN → «без PIN»).

## D-16. Имена устройств хранятся на сервере по IP, в окне можно удалять
- **Решение:** `/api/name` сохраняет имя в `devices.json`; окно показывает список
  «имя + ip» с чекбоксами и кнопкой «удалить выбранные».
- **Причина:** пользователь: «при следующем подключении не запрашивает имя»,
  «сделай в exe список сохраненных устройств с возможностью их выборочного удаления».
- **Последствия:** имя привязано к IP; переезд телефона на другой IP потребует повторного ввода.
- **Статус:** принято. **Источник:** пользователь + код + скриншот.

## D-17. Четырёхэкранный поток с явными кнопками «Загрузить всё» / «Я загрузил всё»
- **Решение:** экран 1 — имя, экран 2 — устройства, экран 3 — отправка, экран 4 — приём;
  кнопка «Загрузить всё» активируется только после `sender_done`; «Я загрузил всё» удаляет Temp.
- **Причина:** подробная спецификация пользователя (см. `PROJECT_CONTEXT.md` §5).
- **Последствия:** получатель осознанно управляет скачиванием; на iOS это снижает риск
  блокировки множественных автозагрузок.
- **Статус:** принято. **Источник:** пользователь.

## D-18. Подтверждение приёма всегда на экране получателя
- **Решение:** всплывающий оверлей «… хочет передать вам файлы. Принять?» + таймаут 180 с.
- **Причина:** пользователь: «подтверждение всегда на экране получателя; ПК — только сервер».
- **Статус:** принято. **Источник:** пользователь.

## D-19. Явный выход из сессии («Назад» + confirm)
- **Решение:** `/api/leave` переводит комнату в Abort с текстом «отправитель/получатель
  вышел из сессии», вторая сторона видит сообщение и процесс прекращается.
- **Причина:** требование пользователя.
- **Статус:** принято. **Источник:** пользователь + код.

## D-20. Выбор LAN-IP с обходом VPN-адаптеров
- **Решение:** `if-addrs` + эвристика: пропускать loopback, штрафовать адаптеры с именами
  vpn/tap/tun/xray/wintun/wsl/hyper-v/vmware/vbox/bluetooth/docker; приоритет 192.168/10.x/172.16-31.
- **Причина:** реальный баг — при включённом VPN окно показывало `172.19.0.1`, телефоны не подключались.
- **Статус:** принято. **Источник:** код + проверка (адрес 192.168.1.25).

## D-21. Текст передаётся отдельным полем, а не файлом
- **Решение:** `POST /api/text?id=&req=` с сырым телом (64 КБ), хранится в `Req.text`
  (20 000 символов, управляющие символы вырезаны), на странице выводится через `textContent`
  и readonly-поле, копирование одной кнопкой.
- **Причина:** пользователь: «чтобы можно было передавать текст… у получателя поле с текстом,
  нельзя редактировать, можно скопировать по 1 кнопке».
- **Статус:** принято. **Источник:** пользователь + проверка (кириллица, `\n`, `<script>` как текст).

## D-22. Удержание экрана телефона через невидимое видео
- **Решение:** пока комната в `ok`, страница играет зацикленное видео из `canvas.captureStream(1)`,
  растянутое на весь экран (`opacity:.01`); Wake Lock API не используется.
- **Причина:** стандартный `navigator.wakeLock` на `http://` недоступен (`isSecureContext=false`);
  при сворачивании экрана iOS/Android душат сеть и передача встаёт.
- **Статус:** принято. **Источник:** проверка на Xiaomi (80+ с экран `Awake` при таймауте 60 с).
- **Ограничение:** видео размером 2×2 не удерживает экран — нужна площадь экрана.

## D-23. Окно не имеет права ронять процесс (`panic` ≠ abort)
- **Решение:** в release `panic = "abort"` убран; отрисовка кадра в `catch_unwind`; сервер поднимается
  один раз в `boot()`, а `run_native` крутится в цикле под `catch_unwind` — при панике окно
  перезапускается (до 5 раз с паузой 500 мс), сервер и передачи живут;
  `panic::set_hook` пишет `%APPDATA%\NeonSend\crash.log`.
- **Причина:** паника egui 0.27 (`hit_test.rs:265`) при клике по исчезающему виджету убивала процесс
  вместе с сервером и передачей. Внутреннего `catch_unwind` вокруг `draw` недостаточно: хит-тест
  выполняется после отрисовки (второе падение 09:18:50 это доказало).
- **Статус:** принято. **Источник:** `crash.log` + журнал событий Windows (`0xc0000409`).
- **Цена:** exe ~5,27 МБ; при падении окно моргнёт и перезапустится (потеря состояния окна).
  Сама паника egui не устранена: она есть во всех версиях 0.27–0.36, исправлена только в 0.37,
  а переход на 0.37 — переписывание окна (новый trait `App::ui`, `Frame::NONE`, `CornerRadius`,
  i8-метрики). Обновление 0.27 → 0.28 сделано, от 0.29+ отличается незначительно.

## D-24. iOS: обход через приложение «Файлы»
- **Решение:** на iOS показывать подсказку и кнопку «Из «Файлов»» (`input` с `accept`
  по расширениям → системный пикер «Файлы» вместо «Фото»).
- **Причина:** пикер галереи iOS не отдаёт большие видео сайту — кнопка выбора неактивна,
  файл не попадает даже в очередь; со стороны сайта это не исправить.
- **Статус:** принято как обход. **Источник:** пользователь + проверка (файл 321 МБ прошёл).

# Часть B. Отклонённые решения

## R-01. Прямая P2P-передача телефон↔телефон (WebRTC) как основной режим
- **Что предлагалось:** DataChannel между телефонами, ПК только сигналинг.
- **Причина отказа:** потолок DataChannel ~10–20 МБ/с, на RTT 50 мс ~2 МБ/с; через один Wi-Fi
  релей обычно не медленнее (узкое место — радио); ломается на client isolation, гостевых
  сетях, разных подсетях; iOS засыпает в фоне; нет прогресса/докачки из коробки.
- **Выбрано вместо:** HTTP-релей через ПК (D-09).
- **Можно вернуться:** да, как надстройку с замером скорости и fallback на релей.
- **Риски при возврате:** сложность сигналинга, поведение Safari с host-кандидатами,
  необходимость TURN для части сетей.

## R-02. HTTPS с самоподписанным сертификатом
- **Причина:** красный экран на Android и предупреждение на iOS при каждом новом сеансе,
  невозможно нормально использовать File System Access API всё равно (не доверенный сертификат).
- **Выбрано:** HTTP (D-03).
- **Можно вернуться:** да, если проект выйдет за пределы домашней сети.
- **Риски:** пользовательские предупреждения браузера, часть API останется недоступной.

## R-03. Локальный CA с установкой профиля на iPhone
- **Причина:** пользователь отказался от установки профилей/сертификатов на телефоны.
- **Выбрано:** HTTP.
- **Можно вернуться:** только при явном согласии пользователя.

## R-04. `neon.local` (mDNS) — удалён 16.11
- **Причина (изначально):** Windows 11 резолвит `.local` нестабильно, Android Chrome часто
  не резолвит вовсе (свой резолвер); нужен надёжный адрес.
- **Что было сделано:** mDNS-ответчик (`src/mdns.rs`, UDP 5353, SO_REUSEADDR), порт 80 первым,
  строка «короткий адрес» в окне; на ПК работало (`Resolve-DnsName`, HTTP).
- **Почему удалено:** пользователь: «короткий адрес не работает на телефоне, ладно его можешь
  убрать». `mdns.rs` удалён, порты снова 8765–8790, `guard` откатан, в окне только `http://<ip>:<port>`.
- **Выбрано:** основной и единственный адрес — IP + QR.
- **Можно вернуться:** если появится клиент, который точно умеет mDNS (Android TV, не Chrome).
- **Можно вернуться:** если появится клиент, который точно умеет mDNS (Android TV, не Chrome).

## R-05. File System Access API для выбора папки сохранения на телефоне
- **Причина:** недоступно вне secure context (а у нас http://LAN), нет в Safari/Firefox,
  на iOS невозможно в принципе.
- **Выбрано:** сохранение через `<a download>`/blob; папку выбирает только ПК-сервер.
- **Можно вернуться:** только с HTTPS и только Chromium desktop/Android.

## R-06. PIN-код на подключение
- **Причина:** подтверждение на экране получателя уже даёт контроль; PIN добавляет трение
  и не защищает от того, кто видит экран.
- **Выбрано:** подтверждение + Host/Origin (D-15).
- **Можно вернуться:** при выходе в недоверенные сети.

## R-07. Продолжать Python-версию
- **Причина:** XSS через innerHTML с именами файлов, нет Host/Origin, нет таймаутов,
  передача не останавливалась при закрытии сервера; пользователь хотел один `.exe`
  с современным интерфейсом.
- **Выбрано:** переписывание на Rust.
- **Можно вернуться:** не нужно.

## R-08. Показывать список файлов на ПК в браузере («обменник»)
- **Что было:** блок «файлы на этом компьютере» со ссылками `/dl?name=…`.
- **Причина отказа:** пользователь: «в целом не нужно пользователю видеть какие файлы есть
  на этом компьютере».
- **Выбрано:** блок и маршрут `/api/files` удалены; `/dl` остался только для файлов комнаты.
- **Можно вернуться:** нет, если не попросят явно.

## R-09. Отдельная страница под каждое устройство
- **Что предлагалось:** сервер генерирует персональную страницу для устройства.
- **Причина отказа:** усложняет кэш/адреса; достаточно одной страницы с серверным состоянием.
- **Выбрано:** одна страница, 4 экрана, состояние с сервера.
- **Можно вернуться:** нет смысла.

## R-10. Автозапуск с Windows
- **Причина:** пользователь сказал, что не нужен: запускает exe вручную.
- **Можно вернуться:** да, если попросят (реестр/задача планировщика).

## R-11. MSVC-тулчейн / установка Visual Studio Build Tools
- **Причина:** нет прав/желания ставить тяжёлые компоненты; GNU-тулчейн работает.
- **Последствия:** несовместимость с некоторыми Windows-крейтами, требующими MSVC.

## R-12. WebView2 / Tauri
- **Причина:** требует установленного рантайма; противоречит «без установки компонентов».

## R-13. Галочка «Отправляю на айфон»
- **Что предлагалось:** ручной переключатель режима нарезки.
- **Причина отказа:** пользователь выбрал автоопределение по UA.
- **Выбрано:** `isApple` по `navigator.userAgent`.

## R-14. Отдавать файлы телефон→телефон в основную папку приёма
- **Причина:** файлы оседали на ПК, пользователь этого не хотел.
- **Выбрано:** Temp-папка (D-09).

## R-15. Считать докачку необязательной и отложить
- **История:** сначала решили отложить, потом пользователь вернулся к теме и докачка была
  реализована (D-11). Решение «отложить» заменено.

## R-16. Ограничиться портом 8765 без перебора
- **Причина отказа:** порт может быть занят; сделан перебор 8765–8790.
- **Побочный риск:** firewall-правило есть только для 8765 (см. `BUGS_AND_ISSUES.md`).
