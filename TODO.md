## Критические (P0)

- [x] **Полный ручной прогон на живых устройствах (iPhone + Android + ПК).**
      Зачем: ни один экран не проверялся на реальном телефоне после перехода на 4-экранный
      интерфейс; все проверки — HTTP и синтаксис.
      Шаги: запустить exe → QR с iPhone → имя → выбрать устройство → подтверждение на втором
      телефоне → отправка 2–3 файлов → проверить файлы и Temp-папку.
      Результат: список расхождений с `PROJECT_CONTEXT.md` §5.
      Файлы: `src/page.html`, при необходимости `src/server.rs`.
      Критерий готовности: сценарий проходит без обходных действий на iPhone и Android.
      Сделано 16.11: Android (Redmi, Chrome) — имя, подтверждение на ПК, передача файла,
      отказ, таймаут, две вкладки; приём на странице ПК в Chrome; телефон→телефон
      (Phone ↔ PC-1) — файлы 25 КБ и 40 КБ в `Temp(от-кому)`, sha256 совпал;
      iPhone (Safari) — передача на ПК (321 МБ, структура MOV целая), имя переживает
      сворачивание Safari, экран не гаснет. Осталось: финальный прогон по чек-листу
      `PROMPT_FINAL_TEST.md` (iOS-галерея, ветки дубликатов, докачка, 5,9 ГБ).

- [x] **Передача текста вместо файлов (16.11).**
      Сделано: `Req.text` + `/api/text` (64 КБ тело, 20 000 символов), панель на экране 3,
      readonly-поле и «Копировать текст» на экране 4, Ctrl+Enter. HTML не исполняется.
      Проверено на телефоне и ПК-браузере.

- [x] **Занятые устройства нельзя выбрать (16.11).**
      Сделано: `busy_ids()` + поле `busy` в `/api/devices`, тег «занято», кнопка disabled,
      отказы в `request` («сам себе», «вы уже в передаче», «устройство занято»).

- [x] **exe больше не умирает от паники окна (16.11).**
      Сделано: `panic = "abort"` убран, `App::draw` под `catch_unwind`, `crash.log`.
- [x] **Окно перезапускается после паники egui, сервер живёт (16.11).**
      Второе падение (09:18:50) показало, что `catch_unwind` вокруг `draw` не покрывает хит-тест:
      сервер вынесен в `boot()`, `run_native` крутится в цикле под `catch_unwind` (до 5 перезапусков),
      eframe обновлён 0.27 → 0.28. Проверено: сборка, тесты 5/5, штатное закрытие окна.
      Не проверено: сам перезапуск (воспроизвести падение не удалось).

- [x] **eframe 0.37 — корень паники egui убран (16.11).**
      Окно переписано под новый API (`App::ui`, `Panel`, `Frame::NONE`, `CornerRadius`, i8-метрики,
      `ctx.copy_text`, `Popup`). Проверено: сборка без предупреждений, 7/7 тестов, 25/25 HTTP-проверок,
      вид окна — скриншотом, страница на Android — без ошибок консоли.

- [x] **exe = только панель, ПК принимает файлы через браузер (16.11).**
      Сделано: подтверждение из окна убрано; браузер на адресе сервера = устройство `PC_ID 0`;
      `push` принимает `Wait|Ok`; экран получателя в `Wait` с оверлеем; `ping` после hello.
      Проверено: приём на странице ПК, два файла подряд, окно без подтверждений.

- [ ] **Git-репозиторий и бэкап.**
      Зачем: истории нет, откат невозможен (риск R-01).
      Шаги: `git init`, `.gitignore` (`/target`), первый коммит; внешняя копия архива.
      Критерий: `git log` показывает коммит, `target` не версионируется.

## Высокий приоритет (P1)

      Проблема: Safari спрашивает разрешение на каждую автозагрузку (B-03).
      Варианты для обсуждения с пользователем: (а) один zip-архив всей комнаты,
      (б) оставить как есть и предупредить в интерфейсе, (в) отдавать файлы по одному
      с кнопкой «далее».
      ⚠️ Решение не принято — требует согласования.
      Файлы: `src/server.rs` (`download`, возможно `/dl?zip=1`), `src/page.html` (`downloadAll`).

- [x] **Правило брандмауэра для 8765–8790.**
      Сделано иначе и проще: правило по программе (`neonsend.exe`, TCP+UDP, любые порты,
      профиль Публичный) — смена порта подключение не ломает. Порт 80 пробуется первым.

- [x] **Проверить и закрыть сценарии отмены/выхода на живых устройствах.**
      Зачем: код есть, живьём не проверялся (кнопки «Назад», «Отмена», сообщение

      Файлы: `src/page.html` (`backFromSession`, `cancelSend`), `src/server.rs` (`leave`, `abort`).
      Сделано 16.11: «Отключить» на ПК проверено; на iPhone «Отмена»/«Назад» не работали
      из-за занятых соединений — починено (`abortUploads`, таймаут+повтор, экран 2 сразу).
      Осталось проверить в финальном прогоне: `leave` и сообщение второй стороне.

- [x] **Прогон телефон→телефон (второй телефон или ПК-браузер).**
      Сделано 16.11: Phone → PC-1, файлы 25 КБ и 40 КБ прошли через
      `Temp(Phone-PC-1-<комната>)`, sha256 совпал, приём подтверждён на втором телефоне.

## Средний приоритет (P2)

- [ ] **Показывать прогресс для больших файлов на получателе (>64 МБ).**
      Сейчас прямая ссылка без прогресса (B-04). Требует либо стриминга в File System
      Access API (только Chromium desktop), либо чанкового скачивания и склейки в памяти
      (риск для памяти iOS) — нужно выбрать осознанно.
      Файлы: `src/page.html` (`downloadAll`).

- [~] **Лимиты и таймауты HTTP.**
      Сделано 16.11: таймаут простоя в `upload` — 60 с без данных → `408`, `.part` остаётся
      для докачки (без tower: `TimeoutLayer` резал бы SSE и большие загрузки).
      Осталось: ограничение числа одновременных соединений (B-09).
      Файлы: `src/server.rs` (`upload`, `start`).

- [x] **Постоянный идентификатор устройства (токен).**
      Сделано 16.11: случайный токен в `localStorage['neon-token']`, ключ `by_token`
      (IP — резерв), имя переживает перезагрузку страницы и смену IP. D-05 изменён.

- [x] **Уникальность Temp-папки.**
      Сделано 16.11: `Temp(отправитель-получатель-номер-комнаты)` (F-36).

- [ ] **Интеграционные тесты HTTP в репозитории.**
      Перенести ad-hoc проверки (`C:\Temp\opencode\m2test2.mjs` и др.) в `tests/` как
      Rust-тесты или задокументированный набор скриптов.
      Критерий: `cargo test` покрывает request→answer→upload→sender_done.

- [x] **Отвязывать комнату после завершения передачи (B-15).**
      Сделано 16.11: `finish_room(Done)` снимает `d.room` у обеих сторон; для комнат «на ПК»
      есть `maybe_finish` (файлы дошли до приёмника → комната завершается сама).
      Проверено вживую.

- [ ] **Финальный прогон по чек-листу `PROMPT_FINAL_TEST.md`.**
      Зачем: после правок 16.11 (текст, занятые устройства, iOS, таймауты, панели окна)
      полный сценарий целиком не прогонялся.
      Критерий: все пункты чек-листа отмечены, расхождения записаны в `BUGS_AND_ISSUES.md`.

- [ ] **Фоновая вкладка теряет SSE → устройство исчезает (B-17).**
      После долгого простоя `prune` убирает устройство, хотя страница опрашивает `/api/ping`;
      помогает только перезагрузка. Вариант: пересоздавать устройство по `ping`+токену.
